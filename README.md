# HALAL-TOWN

HALAL-TOWN — форк Rogue Town, многопользовательской ролевой игры на платформе BYOND и кодовой базе SS13. Основной проект для сборки — `roguetown.dme`. Игровой мир настроен на 60 FPS.

## Требования

- BYOND с Dream Maker (`dm.exe`) и DreamDaemon (`DreamDaemon.exe`).
- Для запуска сервера с базой данных — доступная MySQL/MariaDB и настроенный `config/dbconfig.txt`.

## Быстрый цикл разработки (рекомендуется)

| Команда | Что делает |
|---------|------------|
| `BUILD.bat` | Быстрая сборка (`-DFASTBUILD`); пропускает компиляцию, если исходники не менялись |
| `BUILD.bat run` | Собрать при необходимости и сразу запустить сервер |
| `BUILD.bat force` | Быстрая сборка с принудительной пересборкой |
| `BUILD.bat full` | Полный релизный билд: `DEBUG`, полная карта, `PRELOAD_RSC 2` |
| `RUN.bat` | Запуск сервера без пересборки |
| `RUN.bat -Port 1338` | Запуск на другом порту |
| `RUN.bat -MapThreads 4` | Явно задать число потоков загрузки карты (`0` — поведение BYOND по умолчанию) |
| `RUN.bat -NoInit` | Мгновенный старт без инициализации подсистем (для проверки интерфейса/админки) |
| `BUILD.bat help` | Справка по режимам |

Обёртки вызывают `tools/fastbuild.ps1`. Скрипт сам находит BYOND (`PATH` либо `C:\Program Files (x86)\BYOND\bin`), пропускает компиляцию, если с последней сборки не менялись код и ассеты, и в режиме `fast` передаёт DreamDaemon `-map-threads` по числу ядер. На полной карте этот флаг выигрыша не дал (122,5 с против 100,6 с), поэтому для `full` он не передаётся; переопределить можно через `-MapThreads`. Режим последней сборки хранится в `tmp/.build-mode`; при переключении `fast` ↔ `full` пересборка выполняется автоматически.

`FASTBUILD` включается дефайном `-DFASTBUILD` и меняет только режим сборки:

- без `DEBUG mode` — быстрее сохранение и меньше `.dmb`;
- `PRELOAD_RSC 1` вместо `2` — клиент не выкачивает весь `.rsc` (≈88 МБ) при входе (`0` не используется: `config/external_rsc_urls.txt` содержит внешний URL);
- `LOWMEMORYMODE` — не создаются руины, away-миссии, VR и лишние z-уровни;
- лёгкая карта `_maps/roguetest.json` (158 КБ вместо 770 КБ) — основной вклад в скорость инициализации мира.

Полный билд без этого дефайна остаётся прежним. Лёгкая карта тестовая: если нужно проверять геймплей на основной карте Roguetown, собирайте `BUILD.bat full`.

### Замеры на этой машине (BYOND 516.1673, 16 ядер)

| Показатель | Полный билд | FASTBUILD |
|------------|-------------|-----------|
| Компиляция | 20,5 с | 19,1 с |
| Размер `.dmb` | ≈26 МБ | ≈23 МБ |
| Инициализация мира | 100,6 с | 33,0 с (20,4 с с `-map-threads 16`) |
| Старт сервера до готовности | 107 с | 27 с |
| Runtime-ошибки при старте | 0 | 0 |

Распределение времени до оптимизации: Atoms 34,2 с, Lighting 19,5 с, Mapping 19,0 с, Icon Smoothing 16,5 с, Atmospherics 9,5 с — всё зависит от размера карты. Попутно исправлены две модели без `/turf` в `_maps/map_files/Roguetest/Roguetest.dmm` (добавлен `/turf/template_noop`): они вызывали 138 `list index out of bounds` при загрузке лёгкой карты.

## Полная сборка и запуск вручную

Установите BYOND и запустите компилятор из корня репозитория:

```bat
dm.exe roguetown.dme
```

Сборка с юнит-тестами:

```bat
dm.exe -DUNIT_TESTS roguetown.dme
```

После успешной сборки запустите DreamDaemon из корня репозитория:

```bat
DreamDaemon.exe roguetown.dmb 1337 -trusted -safe
```

Порт можно заменить на нужный. Перед первым запуском проверьте настройки в `config/`, особенно конфигурацию базы данных, если она используется.

## Структура проекта

- `code/` — игровой код на DM: мир, игровые системы, контроллеры, конфигурация и интерфейсные серверные процедуры.
- `_maps/` — конфигурации и карты.
- `tgui/`, `tgui-next/` — веб-интерфейсы.
- `icons/`, `sound/`, `strings/`, `interface/` — графика, звук, тексты и ресурсы интерфейса.
- `config/`, `SQL/` — конфигурация сервера и схемы/миграции базы данных.
- `BUILD.bat`, `RUN.bat`, `tools/fastbuild.ps1` — быстрая сборка и запуск сервера.
- `.autopilot/` — спецификации и состояние задач Autopilot.

## Особенности 60 FPS

Настройки сервера и клиента рассчитаны на 60 FPS. При изменении частоты сервера клиентский FPS синхронизируется с `world.fps`; скорость скольжения рассчитывается с учётом `world.tick_lag`, а подсистема конуса зрения обновляется каждый тик. Подробности разработки находятся в `AGENTS.md`.

**Частота задаётся строкой `FPS 60` в `config/config.txt` и должна совпадать с `world.fps = 60` в `code/world.dm`.** Не включайте `TICKLAG 0.5` — это 20 FPS: `Master.Initialize()` применяет конфиг через `world.change_fps()`, и смена тикрейта уже после старта рассогласовывает ввод (`SSinput`, `SSincone`), задержки ходьбы, `glide_size`, таймеры и кулдауны — действия идут рывками, то быстро, то медленно. При запуске в лог пишется `MC tickrate: ... FPS`; о расхождении конфига и мира предупреждает `WARNING: config number/fps ...`. BYOND квантует `tick_lag` до сотых, поэтому при `FPS 60` в логе будет `63 FPS (tick_lag 0.16)` — это норма (≈62,5 Гц), а не рассинхрон.

Задержки шага (`WALK_DELAY 3`, `RUN_DELAY 2` в `config/game_options.txt`) выравниваются до целого числа тиков макросом `TICK_ALIGN_DELAY` (`code/__DEFINES/movement.dm`, применяется в `/client/Move()`). Без этого 3 дс при `tick_lag 0.16` = 18,75 тика: `world.time` идёт только целыми тиками, поэтому при зажатой клавише шаги чередовались бы 18/19 тиков — та самая «рваная» ходьба. Проверка кратности есть в юнит-тесте `movement_incone_sanity`.

Скольжение должно быть детерминированным: `GLOB.glide_size_multiplier` зафиксирован в `1.0`, а `SStime_track` больше не пересчитывает его из `tick ratio` каждые 10 с (раньше он прыгал `0.75…1.25`, и `DELAY_TO_GLIDE_SIZE` читал его на каждом шаге — персонаж визуально то ускорялся, то тормозил при неизменной задержке шага). Телеметрия `time_dilation_*` сохранена. Кроме того, `Master` при перегруженном тике больше не делает `continue` (пропускавший `SSinput`/`SSincone`), а лишь урезает бюджет тяжёлых подсистем.
